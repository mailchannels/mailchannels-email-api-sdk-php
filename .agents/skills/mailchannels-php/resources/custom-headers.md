# Custom Email Headers

Use `headers` for application-specific metadata, tracking IDs, campaign tags,
or any custom `X-…` header.

## Root vs Per-Personalization

- **Root `headers`**: applied to every personalization.
- **Per-personalization `headers`**: applied only to that personalization.
- **If the same header is in both places, the personalization value wins.**

```php
use MailChannels\Message\{EmailAddress, EmailParams, Personalization, Content};

$client->emails->queue(
    new EmailParams(
        from: new EmailAddress('sender@example.com'),
        subject: 'Hello',
        content: [Content::plain('Hello')],
        headers: [
            'X-Campaign-ID' => 'newsletter-2026-05',
            'X-Project'     => 'growth',
        ],
        personalizations: [
            new Personalization(
                to: ['alice@example.net'],
                headers: ['X-Tier' => 'pro'],
            ),
            new Personalization(
                to: ['bob@example.net'],
                headers: [
                    'X-Tier'        => 'free',
                    'X-Campaign-ID' => 'growth-override',
                ],
            ),
        ],
    )
);
```

## Reserved Headers — Never Set These

MailChannels controls a fixed set of message headers. The SDK pre-validates
and raises `ValidationException` client-side before any request that tries
to set one of them. Header names are checked case-insensitively.

These headers are either generated by the API itself or derived from
structured payload fields:

| Reserved header | Set via payload field |
| --- | --- |
| `From` | `from` |
| `To` | `personalizations[].to` |
| `CC` | `personalizations[].cc` |
| `BCC` | `personalizations[].bcc` |
| `Subject` | `subject` (root) or `personalizations[].subject` |
| `Reply-To` | `replyTo` (root) or `personalizations[].replyTo` |
| `DKIM-Signature` | `dkimDomain` / `dkimSelector` / `dkimPrivateKey` |
| `Content-Type`, `Content-Transfer-Encoding` | `content[].type` |
| `Message-ID` | Returned in `results[].messageId` |
| `Authentication-Results`, `Received` | Generated by the API |

The reserved list is enforced by `MailChannels\Message\EmailHeaders::validate()`.
Attempting to set any of them raises `ValidationException` with error code
`ReservedHeader`.

## Case Sensitivity

Header names are treated case-insensitively by MailChannels. If two keys
differ only by case, only one is used and the choice is unspecified. Pick one
canonical casing per header.

## Values

Both keys and values must be strings. Pass only `array<string, string>` — any
non-string key or value raises `ValidationException` before the request leaves
the client.
